Test-time training and memory for robot policies

RoboTTT (Jiang et al., NVIDIA / Stanford / UT Austin, July 2026)

Nir Pechuk · Continual learning reading group

How can we learn from our test-time experience?

Outer loop · slow weights $\theta$ and $W_0$ · gradient descent on $\mathcal{L}_{\text{outer}}$ over training sequences
Inner loop · fast weights $W_t$ · gradient descent on $\mathcal{L}_{\text{inner}}$, at train and test time
$W_0 \to W_1 \to \cdots \to W_t \to \cdots$
$$W_t \leftarrow W_{t-1} - \eta\,\nabla_W\,\mathcal{L}_{\text{inner}}\!\big(f_{W_{t-1}}(K_t),\,V_t\big)$$
(inner: what to remember)
$$O_t = f_{W_t}(Q_t)$$
(apply: what to retrieve)
$$\min_{\theta,\,W_0}\ \mathbb{E}\Big[\mathcal{L}_{\text{outer}}\big(\text{task};\ \theta,\ W_T(\theta, W_0)\big)\Big]$$
(outer: what memory is for)

Choosing $\mathcal{L}_{\text{inner}}$ and $\mathcal{L}_{\text{outer}}$ is choosing how we hope to use test-time experience.

Highlighted: what today's papers look like mechanically.

In robotics, the feedback is the context is the examples.

  • Mechanically, we use the inner and outer objectives designed for history reconstruction.
  • Functionally, this buys us learning-from-feedback and learning-from-examples as well.
  • Remaining design questions: what to put in memory, and where in the model should memory be?

Preliminaries: a VLA with a flow-matching action head.

$$\pi_\theta\big(A_t \mid o_t, q_t, l\big),\quad A_t = [a_t,\dots,a_{t+H-1}]$$
(a chunk of H actions)
$$\textcolor{#B4722A}{A^{\tau}} = \tau A + (1-\tau)\,\epsilon,\qquad \epsilon\sim\mathcal N(0, I)$$
(noising; τ = 1 is clean data)
$$\mathcal L = \mathbb E_{\tau,\epsilon}\,\big\|\textcolor{#B4722A}{v_\theta}\big(\textcolor{#B4722A}{A^{\tau},\tau},\textcolor{#2A7B76}{\Phi_t},q_t\big) - (A-\epsilon)\big\|^2$$
(flow-matching loss: predict the velocity)
$$\textcolor{#B4722A}{A^{\tau+\delta} = A^{\tau} + \delta\, v_\theta(\cdot)},\qquad \tau: 0\to 1 \text{ in } k \text{ steps}$$
(inference, k ≈ 4–10 steps)

Mechanism: attention within a timestep, TTT across timesteps.

$$\textcolor{#1849C6}{W_t} \leftarrow \textcolor{#1849C6}{W_{t-1}} - \eta\,\nabla_W\big\|f_{W_{t-1}}(K_t) - V_t\big\|^2$$
(update, same as TTT layers)
$$O_t = f_{\textcolor{#1849C6}{W_t}}(Q_t)$$
(apply)
$$O = \tanh(\alpha)\odot O_{\text{TTT}} + O_{\text{attn}}$$
(gate, α init 0.001)
  • Placement: one TTT layer after each of GR00T N1.7's 16 DiT layers. Fast model is a 2-layer MLP, about 10M params per layer.
  • Gate starts near zero, so the pretrained policy is untouched at step 0 and learns how much memory to use.

Training recipe: how to make this work at 8K timesteps.

Sequence action forcing

$$\mathcal{L}_{\text{fm}} = \tfrac{1}{T}\textstyle\sum_{t}\ \mathbb{E}_{\tau_t,\epsilon}\big\|v_\theta(\,\cdot\,;W_{t-1}) - (A_t-\epsilon)\big\|^2$$
$$A_t^{\tau_t} = \tau_t A_t + (1-\tau_t)\,\epsilon,\qquad \tau_t \text{ drawn per chunk}$$

One noise level per chunk, not per sequence. Shared noise makes whole sequences uniformly easy or hard; training is unstable without this.

Truncated BPTT

Fast weights carry across segments, gradients are cut. GPU memory scales with segment length, not context length. $W_0$ still gets gradient through segment 1.

Fast weights let us learn how to use heterogeneous data.

Mixed quality: DAgger distillation

  • Remember the entire trajectory, but only update slow weights on the correction behavior.
  • Learn when to respond to a failure and the mapping failure → correction, not just the corrections in isolation. They position it as "Algorithm Distillation through meta-learning."

Mixed modality: in-context human video

  • No action labels in a video, but the inner loss is self-supervised, so the video still updates $W$.
  • Prime the memory with the human video; at train time, use slow weight updates on a paired robot trajectory, and at test time, this will produce in-context learning.

  • Naive history hurts: adding one history frame drops Pup Go Car from 57% to 39.5%. Spurious correlations, out-of-distribution at test time.

  • Qualitatively: tracks stage progress under state aliasing, retries a missed screw, uses past views of now-occluded parts.

Context length as a scaling axis

  • 128 → 8K: steady gains with no saturation. 71.5% at 8K vs 43.9% for the same model at 1K. Gated Delta-Net doesn't collapse from context, but doesn't scale.
  • Their explanation: $W_0$ and the update dynamics are meta-learned, and longer sequences give the outer loss more inner steps to shape. A linear associative state has nothing to meta-learn.

Past experience for learning from feedback: DAgger distillation

  • Standard DAgger (train on corrections only): +9% average, +13% on the sequence models.
  • DAgger distillation (whole trajectory in memory, loss on corrections only): +36% RoboTTT, +29% GDN.
  • Robot actions are useless as targets (GR00T: full trajectory = corrections only = 57%) but useful as context.

Ablations: what the design decisions bought

  • No sequence action forcing: collapses. Inaccurate motions, no progress.
  • Linear fast model beats GR00T but is 27% below the 2-layer MLP. Nonlinear compressors matter, as in the vision and language TTT results.
  • Roadmap: state tokens only → + action tokens (+23%), the model knows its own past actions → + register tokens (+18%).
  • Registers do nothing for GR00T alone. They only help when there is a temporal mechanism to carry them.

Two questions on the way to T²Mem

Why are we putting memory into the action head? Would it be more useful to remember observations?

  • RoboTTT keeps the VL tokens out of TTT "for computational efficiency"; 16 registers stand in for them.
  • Their own limitations section asks for robotics-oriented objectives for the TTT layers.

Robot streams are strongly correlated with few surprising moments. Do we need to memorize each time step equally?

  • The pitch is that TTT "retains salient features and discards redundant ones", but the update rule treats every step the same.
  • Titans already asked this for language with surprise-driven updates.

How do we make memory preserve information that matters for downstream robotic decisions?

What counts as a memory-dependent task

$$\sup_{\pi\in\Pi_{\text{hist}}} J(\pi)\ >\ \sup_{\pi\in\Pi_{\text{current}}} J(\pi)$$
(the current observation is not enough; RoboMME, 16 simulated tasks in four suites)

Why not remember the observations themselves?

$$U_t = \operatorname{Attn}\big(Q_{\text{if}}(E_t),\ K_{\text{VL}}(\textcolor{#2A7B76}{\Phi_t}),\ V_{\text{VL}}(\textcolor{#2A7B76}{\Phi_t})\big)$$
(16 learned queries over the VL tokens only)
$$Q_t = U_t\theta_q,\qquad R_t = f_{\textcolor{#1849C6}{W_t}}(Q_t)$$
(read)
$$K_t = U_t\theta_k,\qquad V_t = U_t\theta_v$$
(bindings to write)
$$\tilde U_t = U_t + \tanh(\alpha)\odot R_t$$
(gated fusion → keys and values for the action expert)

Do we need to memorize each time step equally?

$$a_t = \cos\angle\big(-g_t,\ W_t - W_0\big)$$
(alignment with the path so far)
$$r_t = \frac{\lVert f_{W_t}(K_t) - V_t\rVert}{\lVert V_t\rVert}$$
(relative residual; normalization dropped)
$$\beta_t = \operatorname{smoothstep}\!\Big(\tfrac{1}{2}(1 - a_t)(1 + r_t)\Big)\ \in [0.1,\,1]$$
(write scale; clipping dropped)
$$W_{t+1} = W_t - \eta_t\,\beta_t\,g_t$$
(gated update)
  • Early memories survive with 19–47% less error. This is retention, not task success.
  • Not quite Titans: no momentum, no forgetting. It only attenuates redundant writes. $\eta_t$ is curvature-calibrated with one learned multiplier per layer (backup).
  • Still a hard-coded heuristic for a deeper nested optimization problem (→ conclusions).

Alternating memory–policy learning

  • Stage 1: adapt π0.5 to the tasks with no memory.
  • Stage 2A, learn to remember: policy frozen. Action gradients flow through the frozen AE into the memory's slow parameters: interface, projections, $W_0$, step multipliers, gates.
  • Stage 2B, learn to act: memory slow parameters frozen. The policy (and the VLM LoRA feeding the memory) adapts to the readouts. 500 steps each, repeated.
  • Joint training ≈ no memory at the same budget. Each module keeps chasing the other's moving representation.
  • In our framing: coordinate descent on the outer objective, each group with a fixed counterpart. The inner objective never changes.

Does the policy actually use the memory, and what does it cost?

The counterfactual pair behind (b): same instruction, same final scene, different history, different correct container. Expert demonstrations from the project page, not policy rollouts. Video: yzliu84.github.io/T2MEM-project

  • Writes disabled (keep $W_0$ and reads): −83 / −65 / −41 points on VideoUnmask / SwingXtimes / MoveCube.
  • Counterfactual memory on VideoUnmask: correct 300/300, conflicting 1/300, empty 101/300. Empty is chance; wrong is worse than nothing.
  • Write timing: 8 pre-occlusion writes match all 16 (77%); 8 post-occlusion writes get 21%. Memory forms while the evidence is visible.
  • Cost: the memory stage adds 7.7 ms. End to end 3× faster than the best RoboMME method and 69× faster than MemER's external planner.

Conclusions and my thoughts

What this says about TTT itself

  • Adaptive updates seem like a hard-coded heuristic for just further nesting the optimization problem and having even more frequencies of weights that control deeper optimization problems; see Nested Learning.

Where else memory could live

  • We know memory as context, layer, and gating, but what about as a separate expert with cross-attention?

How I would integrate it into robotics

  • No new module or gating, In-Place TTT style.
  • We can also take the more tailored inner objective like In-Place TTT or any of the exploration papers.

RoboTTT tasks and rubrics

RoboTTT training details (Appendix A)

  • Backbone: GR00T N1.7 = Eagle VLM + 538M-param DiT. One TTT layer per DiT layer (16), ~10M each, 690M total.
  • Fast model: 2-layer MLP with GeLU; plain gradient descent in the inner loop; learned inner learning rate on a base of 0.1; RoPE with θ = 10000.
  • Pretraining: tabletop bimanual robot data + egocentric human video (EgoScale), curated for long trajectories. Only the new sequence layers train. 16 GB200, 30K steps, WSD schedule, peak LR 2e-5. Batch 64 up to 4K context, 16 above.
  • Post-training: per task, 1K context, batch 1 per device, all parameters, 8 GPUs, 20K steps, cosine, peak LR 5e-5.
  • Deployment: YAM bimanual, four RealSense D405 at 480p, RTX 5090, 30 Hz.
  • GDN baseline: Gated DeltaNet from flash-linear-attention, same placement, gating and parameter count.

T²Mem: curvature-calibrated step size (Appendix A.1)

$$G = \lVert g_t\rVert^2,\qquad C = \frac{2\,\lVert J_f\, g_t\rVert^2}{H_m N d}$$
(gradient norm, curvature proxy; per head)
$$q = \operatorname{clip}_{[10^{-12},\,10^{3}]}\big(G / \max(C, 10^{-30})\big)$$
(trial step)
$$b = \frac{L_h(W_t - q g_t) - L_h(W_t) + G q}{q^2}$$
(measured curvature along $g_t$)
$$\ell_t = \min\!\Big(10^3,\ \begin{cases} G/\max(2b,10^{-30}) & b>0\\ q & b\le 0\end{cases}\Big),\qquad \eta_t = \tfrac{1}{2}\operatorname{softplus}(\rho)\,\ell_t$$
(step size; one learned $\rho$ per layer, init so the multiplier is 1)
$$W_{t+1} = W_t - w_t\,\eta_t\,\beta_t\,g_t$$
(with $\beta_t$ from the surprise gate)

$\beta_t$ and the calibration are stop-gradient. Outer gradients still flow through the fast-state recurrence, $g_t$, the projections and $\rho$. The "fixed $\beta=1$" control keeps this calibration.
